PERQemu "experiments" branch ChangeBlog


Summary of changes on the development branch since the v0.8.5 interim release.
Previous notes moved to ChangeLog-Old.txt.


May, 2026:

    8. So few rabbits, so many rabbit holes.  Fix a regression in the floppy
    controller after recent changes to the scheduler and how resets are handled.
    Was preventing floppy boots from working reliably.  Bump to v0.9.3 for debug
    and testing push before next release.
    
    7. Whoops.  The Zilog SIO "Auto Enables" stuff (and that chip in general) is
    just bonkers.  Rework the serial Tx/Rx routines to properly test/use the bit
    when set (as the PERQ generally does enable it).  Also refactor the dynamic
    reconfiguration stuff so all programming registers are properly restored
    when Speech or RS232 devices are re-enabled; it sort of all actually works
    now, mostly, kind of.  Checkpoint for more debugging.

    6. The "force bad parity" diagnostic function is now implemented, sort of.
    There are at least three different ways a parity error is reported based on
    the type of memory board, and I'm just doing the most straightforward one
    for now.  Of course this isn't documented at all, except in some extremely
    obscure microcode source, with additional clues in fuzzy scans of the old
    schematics.  As this mainly adds overhead and really isn't useful for normal
    operations, it's currently #ifdef'ed out.

    5. Running the ICL confidence test microcode and finding obscure - and very
    questionable - corner cases.  May have to actually implement memory parity
    error reporting, which apparently differs according to board peculiarities
    that are only "documented" in microcode source?  Of course.  Nothing is EVER
    easy.

    4. Speech/audio output rate is dynamically adjusted based on host emulation
    rate, centered on the 60fps real-time rate.  The range is clipped from a low
    of 20fps to a high of 100fps (when CPU rate limiting is disabled).  A new
    Settings option ("rate limit speechdelay") turns OFF this adjustment; the
    unimplemented FrameSkipping rate limit has been removed.  UserGuide updated;
    bump to v0.9.2.

    3. Unwind extended debugging stuff and start turning down the logging noise
    for serial/speech/Z80 stuff.  Some lint and fluff removal.  Push the changes
    for RS-232 port reconfiguration.  Debugging continues.

    2. Fixed up speech output to not stutter due to silly scheduling bug.  Some
    testing on Linux/Windows serial ports yielding positive results; much more
    to do.  Trying to push fixes in more manageable chunks, but this branch is
    still very much in flux as debugging continues.  Version number bump and/or
    interim release with User Guide update when stable again.

    1. Side project writing diagnostic microcode to help a friend with hardware
    debugging.  Pushed out the interim update just to "clear the decks" but do
    NOT recommend building or running it as there are several minor incompatible
    CLI changes that introduce minor errors in Settings or Configuration files;
    next push should resolve numerous Speech and RS-232 issues and clean up a
    ton of haphazard or purely extraneous debugging instrumentation.


April, 2026:

    1. Updates to the User Guide and CLI to support new serial stuff.  Testing
    of USB/serial exception handling and dynamic reload ongoing.  This push to
    try to swap back in some context for what the hell I was working on last
    month before distractions IRL pulled me away from development.  Expect this
    update is shaky at best; look for an update forthwith.


March, 2026:

    2. SIO/RS-232/Speech refactoring and testing is slow and painstaking, but I
    am working out the kinks.  Haven't fallen off the map.  Just struggling to
    find time/energy/focus/flow to get it done.

    1. While the human race is busy Great Filtering itself into extinction, I've
    put back together the Z80 SIO implementation and reworked all of the serial
    devices.  It is painstakingly documented "for posterity" (ha, ha ha haahaha)
    in Docs/SerialPorts.txt.  RSX: file copies now write the host's native line
    endings (CRLF on Windows, LF on Unix).  Bump to v0.9.0 as we close in on a
    v1.0.0 release and/or the fall of civilization.


February, 2026:

    2. Serial port rewrite in progress.  This is artisinal, 100% organic, free
    range RS-232 emulation from the clear bitstreams of the Pacific Northwest.

    1. Went down a rabbit hole to investigate a proper refactoring of the Z80's
    serial handling (RS-232 and audio).  Had a great visit from Josh (IRL!) and
    exchanged a pile of media and discovered that we do, in fact, have a copy of
    PNX v4 and -- possibly -- some bloody PNX v5 source code!!  Very excited
    that I might *finally* be able to diagnose why v5 will not boot.  (PNX v4
    boots just fine, but as with the PNX v3 set the media needs to be re-imaged
    to capture track 0.)  Along with the last of the 150+ QIC tape images, there
    are many more goodies to eventually add to the Bitsavers/PERQmedia pile!


January, 2026:

    8. Push to capture audio changes that I'm about to undo.  Third time's a
    charm, right?  This works across platforms but is needlessly complex and I
    think I've worked out the better solution.  Hang tight.

    7. Hmm.  RS-232 is _better_ but it can get itself thoroughly wedged if flow
    control isn't handled correctly.  Which it isn't.  Wired up the pin change
    notifications (probably broken on Unix, but we'll see?) to see if that makes
    any difference.  Getting handshaking to behave properly on three platforms
    is going to be "challenging."

    6. Audio refactoring: take two.  Windows 10 (on my stupid test PC) was mute
    until I forced the use of the "dsound" driver instead of the default; this
    may have to be configurable.  Changed the strategy to open the device once,
    using common 16-bit/44.1Khz/mono (as "CD quality" ought to be a very common
    rate that any modern host can match); if the driver insists on 2 channels at
    the minimum, accommodate it.  If your host can produce mono output and you
    find it weird or disconcerting, you can tell the emulator to do fake stereo
    output through a debug command or possible Settings option?

    5. Small fix to the file logging setup on a new host: not picking up initial
    default (or changes to) the output directory setting correctly.  Now creates
    (if needed) and rescans the directory when file logging is enabled.  Small
    corrections to the Kriz tablet to offset a slight regression in IOB configs
    due to SIO/Speech changes.

    4. Ethernet fix: sort of.  On a "quiet" dedicated network, don't pass any
    traffic to the PERQ until the FCS probe has been completed, or it'll blow
    up POS's fragile network stack.  Someday I plan to update PERQ Kermit, the
    FTP client, Accent Speak/Listen, and MUCH more of the original software to
    be way, way more robust on a modern network.  Alas.  The crude fix here may
    cause POS some delays but Accent is more resilient and shouldn't be affected
    as much.  (Will revisit when speech/audio is working.)
    
    3. RS-232 update: refactored ISIODevice interface, added separate Tx/Rx baud
    rate support on EIO (only affects pacing for the PERQ side, not the host),
    and implement polling on Unix for the receiver since the C#/Mono SerialPort
    class never actually fires the damn DataReceived event.  Some limited tests
    with Chatter, Kermit and Putty/TeraTerm show that PERQ<->PERQ transfers are
    already much more reliable, but much work remains to work out a flow control
    strategy to prevent overruns when a fast host dumps a crap ton of data on
    the PERQ.  Bump to v0.8.9 for platform testing.

    2. Small update: make Windows Ethernet device selection a bit less annoying.
    Tiny bug fix in PERQmedia to make sure version # byte is set when writing to
    IMD images; in some cases it was left at zero when converting a floppy from
    another format to IMD.

    1. Didn't quite get to v1.0 by the end of 2025, but came pretty darn close.
    Audio refactoring (and Z80 SIO/DMA rework) and other improvements on track
    for a v0.9.x release in the coming weeks?  Revising the to-do lists and
    updating the roadmap for the final push; improvements to all of the utility
    programs (PERQdisk and Stut) and media library updates in the works too.
