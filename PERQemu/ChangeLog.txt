October, 2025:

    2. Bump the version of SDL2-CS and PacketDotNet.  To maintain compatibility
    with the current .NET Framework build environment, specific versions are
    used (far from the latest).  Probably nobody else on the planet cares about
    running this on platforms this old, using Mono... so here's fair warning
    that very likely, come 2026, the minimum system requirements will finally
    shift toward something slightly more up-to-date.

    1. If PERQemu detects that you are attempting to run PNX 5, it will delete
    itself from your hard drive and report you to the FBI.  PNX 5 is a fake OS,
    a hoax, it doesn't exist, we have always been at war with Eastasia.

    The patches/mods here roll up some of the latest attempts to address the
    numerous bugs and outright bizarre behavior exhibited by the PNX 5 kernel.
    Despite improving the near-cycle-accurate behavior of the emulator by making
    it more faithful to the hardware, PNX 5 remains stubbornly, stupidly broken.
    Without source code or a shred of documentation, further effort is pointless
    so I'm setting it aside for now.

    Pushing an interim update to clear the decks and shifting focus to pressing
    UI matters (screen size and keyboard mapping).  Bump to v0.8.0.


September, 2025:

    2. More Ethernet testing and tuning; POS TestEther, FTP, Accent services
    are working with better reliability.  That is to say, as well as can be
    expected given how fragile and bare bones a lot of that original software
    is, but it's exciting to see Accent living up to its billing as a network
    OS and distributed computing environment.  Many ideas cooking for how to
    help manage/integrate VMs with any existing host network infrastructure.

    1. Debugging.  Refactoring the Ether10MbitController because it was getting
    unwieldy.  Now 50% more wieldy.  Bumped version to v0.7.9 and push for some
    platform testing.  PNX 5 is still intransigent.


August, 2025:

    3. Pushed v0.7.8 to main for pre-release.  Dug into the PDMA/FIFO stuff yet
    again for PNX but it's failing before any of that.  Has to be a memory state
    machine issue (they abuse the living hell out of the overlapped fetch/store
    rules) but still haven't nailed it down.

    2. Small victory: FLEX now runs, thanks to an RTC clock fix.  New settings/
    configurator commands to save an RTC offset so the virtual machine can party
    like it's still 1989.  PERQ-2 VT100-style keyboard mappings need fixin'.
    Updates to the UserGuide for recent changes.  Push for testing prior to 
    v0.7.8 pre-release.

    1. Video updates.  Memory state updates.  Fixing "bugs" that improve the
    accuracy and completeness of the emulator without actually affecting the
    behavior of any of the software it runs: are they really bugs after all?
    Update to push out custom build to support additional FLEX media recovery.


July, 2025:

    4. Memory state table corrections to enhance accuracy of two-word fetch and
    store operations, add missing indirect/overlapped Fetch2 state.  Force clear
    the two least significant bits for DMA transfers, since PNX 5 apparently 
    violates the quad-alignment requirement there too (expecting the hardware to
    do it) but that doesn't make a damn bit of difference either.  Additional
    debugging and logging tweaks.  PNX 5 still f&*$)ing broken.  This has become
    absolutely infuriating.  Interim push for platform testing.

    3. Pushed udpates for Accent S6 + Lisp M3 to the PERQmedia archive.  Added
    a reconstruction of the PNX C-Codes from PNX 5 based on scrounging through
    binary dumps of the assembler, verified by manually reconstructing ~ 2000
    lines of the microcode interpreter.

    2. Oooh.  Accent S7 booted in 24-bit mode with 4MB of memory!  Fixed bug in
    Upper() on the 24-bit CPU and restored address wraparound on the 4MB memory
    board (despite what Accent kernel comments in the sizing loop say, it DOES
    wrap, otherwise VFY fails -- there's no 24-bit VFY microcode to be found.)

    1. More debugging. More Ethernet tweaks. No success with PNX 5 or FLEX yet.
    Discovered the cause and removed the hack for the Z80 DMA issue manifested
    by FLEX thinking the Z80 load was timing out.  Discovered that telling the
    Z80 to execute the version number bytes when jumping to the (wrong) start
    address in RAM is perfectly fine, apparently.  Slight update to the debug
    logging so I can crank the verbosity to Proustian levels.  Added NAT table
    entry aging, but forget why.  How can we hack when the world is burning?

    6. Oh bloody hell.  Missed one small fix to the MFM/Microp disk controllers.
    The BOOT ROM tells the disk controller to ship the normal two quad words for
    the logical header but sets the high address bits so the buffer will always
    end up in high memory regardless of what size board is installed -- and then
    ignores the header bytes anyway.  Ugh.  The disk hardware/state machine must
    rely on always sending those two quads even though the DMA hardware could be
    programmed to skip it by changing ONE CONSTANT in the microcode, but ANYWAY
    it means we take out the range check and just let our Memory implementation
    wrap the address, like the hardware do.  Gotta love it, warts and all.

    5. Small Ethernet bug fix when fetching the machine's MAC address.  Update

January, 2025:

    4. Finally revisited the CPU Victim register implementation, and after more
    careful study of the schematics corrected the emulation to be more faithful
    to the actual hardware.  This has eliminated the need for the PNX "DDS 142"
    boot bug (although their 16K VFY test code is still janky as hell and may
    not actually test what they think it does).  The microcode patch that was
    slapped together for earlier PNX versions has been removed.  PNX 5, however,
    has some sort of video or RasterOp problem, where characters are randomly
    painted incorrectly and the kernel drops into the debugger shortly after
    boot.  This may be a bad boot floppy?  Investigation underway.  A couple of
    small bug fixes to correct the previous commit (something that compiled on
    Xamarin Studio threw an error on VS2022, first time that's happened).  This
    should build correctly.

    3. Updated the video display handling so that the floppy activity icon is
    now visible during slow floppy boots.  It's pretty subtle so you might not
    notice it.

    Also:  POS G.85 booted from floppy.  Don't have full installation media or
    any sources (dang) but may have a tape image to load.  This one is super
    rare.  PNX 3 installation dead in the water, as most of the floppies
    are missing cylinder zero.  This is typical for POS floppies, but PNX DOES

    diskettes are re-scanned.  Bummer.  It has demos?  Working on PNX 5 boot

    bit CPU with working DMA (but a video glitch that needs investigation).
    All of this is definitely NOT procrastination, no way, not at all.  Nope.
